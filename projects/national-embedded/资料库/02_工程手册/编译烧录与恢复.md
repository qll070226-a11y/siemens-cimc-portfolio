# 编译、烧录与恢复

## 构建入口

- APP：`APP/MDK/CIMC_APP.uvprojx`
- Bootloader：`BootLoader/MDK/CIMC_BL.uvprojx`
- 批量构建：工程根目录 `tools/rebuild_keil.bat`
- 产物核对：`tools/verify_build_outputs.ps1`

## 正确构建顺序

1. 关闭可能占用同一工程的其他 Keil 实例。
2. 先构建 APP，查看最后一行错误和警告计数。
3. 改动升级或地址时，再构建 Bootloader。
4. 运行产物核对脚本，检查时间戳和文件大小不是旧文件。
5. 保存 `build.log`，不要只看 Keil 状态栏。

## 烧录组合

### 只调 APP

调试器若支持指定地址，可将 APP hex 烧到 `0x08011000`。如果整片擦除后只烧 APP，MCU 从 `0x08000000` 启动，通常不会自动到 APP，因此应同时保留 Bootloader 或通过调试器直接运行 APP。

### 完整运行

1. 烧 Bootloader 到 `0x08000000`。
2. 烧 APP 到 `0x08011000`，不要整片擦除覆盖第一步。
3. 复位，Bootloader 检查 APP 栈指针和复位向量后跳转。

## 常见构建故障

| 现象 | 优先检查 |
|---|---|
| 找不到 ARM Compiler | Keil Manage Project Items/Target Toolchain；本机 ARMCLANG 6.24 |
| 找不到 GD32 头文件 | Pack 路径、工程 Include Paths、是否移动 APP 子目录 |
| 重复定义中断 | 工程中只保留比赛版 IRQ 文件，避免原中断文件同时参与编译 |
| FreeModbus 类型冲突 | `APP/HeaderFiles/port.h` 兼容头；FatFs 与 FreeModbus typedef |
| 多个 port 文件符号重复 | 只选择 `contest_port_clocked.c` |
| 多个 storage 文件重复 | 只选择 `contest_storage_final.c` |
| 构建成功但产物未变 | 核对输出目录、时间戳和 build.log 的工程路径 |

## 现场恢复策略

- 保存三个副本：原始模板、最近可编译版、当前修改版。
- 每完成一个评分功能，复制一次最近可编译版。
- 遇到硬故障先烧回已知可运行的 Bootloader + APP，区分软件与接线问题。
- 不使用 `Clean` 代替备份；Clean 只能删中间产物，不能恢复源码。
