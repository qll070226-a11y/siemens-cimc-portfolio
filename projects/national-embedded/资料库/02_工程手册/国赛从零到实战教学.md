# 2026 CIMC 工业嵌入式系统开发国赛从零到实战教学

> 适用对象：第一次参加西门子杯工业嵌入式系统开发方向、已经具备开发板和基础 C 语言能力，但不熟悉正式赛场工作流的选手。  
> 配套工程：`CIMC_2026_国赛工程模板`。  
> 最高原则：正式赛题和裁判现场说明始终高于本教程。

## 1. 你目前所在的阶段

你已经完成第一项关键硬件验证：PC 通过 USB-RS485 成功读取开发板的 Modbus 输入寄存器。

```text
TX  01 04 00 00 00 01 31 CA
RX  01 04 02 00 00 B9 30
```

这证明 COM6、19200 8N1、从站地址 1、A/B 接线、开发板 APP、FreeModbus 接收与回复链路均已基本正常。响应数据 `00 00` 只是 30001 当前值为 0，不代表通信失败。

下一阶段应依次验证：六个寄存器、连续轮询、三通道测量、标定、TF 卡、异常处理和长时间稳定性。不要直接跳到固件升级。

## 2. 国赛到底在考什么

这类比赛不是单纯考写 C 代码，而是考能否把正式需求稳定落到完整嵌入式系统上：

```text
正式赛题
  ↓ 拆解
软件需求 + 硬件接口 + 协议 + 数据格式 + 提交要求
  ↓ 实现
采样 → 换算 → 状态 → Modbus → TF存储 → 上位机
  ↓ 验证
构建日志 + 报文 + 标定表 + CSV + 异常测试 + 长稳记录
  ↓ 交付
源码 + HEX/BIN + PCB资料 + 说明材料 + 答辩证据
```

| 能力 | 典型任务 | 常见失分原因 |
|---|---|---|
| 需求理解 | 地址、倍率、周期、异常条件 | 凭印象实现、地址差 1、遗漏单位 |
| 工程实现 | 驱动、调度、协议、文件系统 | 写了代码但没接入 Keil 工程 |
| 实物验证 | 精度、通信、存储、稳定性 | 只证明编译通过，没有实测证据 |
| 交付表达 | 文档、材料、答辩、匿名 | 文件不全、命名错误、泄露身份 |

必须形成习惯：每条需求都写清“代码位置、验证方法、验证结果”。

## 3. 认识当前工程

### 3.1 数据主链路

```text
GD30AD3344 三通道 ADC
        ↓
contest_adc.c：读取 ADC 端电压
        ↓
contest_app.c：换算 mA/V、断线判断、采样计数
        ├────→ contest_modbus.c：发布 30001~30006
        └────→ contest_storage_final.c：写 TF 卡 CSV
```

APP 采用无操作系统合作式调度：

| 任务 | 默认周期 | 作用 |
|---|---:|---|
| Modbus | 1ms | 调用 `eMBPoll()` |
| 三通道采样 | 100ms | 更新测量值和寄存器 |
| TF 日志 | 1000ms | 追加 CSV |
| 告警 | 100ms | 原工程告警逻辑 |
| UI | 50ms | 原工程显示逻辑 |

某个任务阻塞会推迟其他任务，因此不要在任务中增加无限等待、长延时或大量同步打印。

### 3.2 最常修改的文件

| 文件 | 主要职责 |
|---|---|
| `APP/HeaderFiles/contest_config.h` | 地址、波特率、周期、通道、增益、偏移、阈值 |
| `APP/Function/contest_app.c` | 换算、滤波、断线和状态逻辑 |
| `APP/Function/contest_modbus.c` | 寄存器地址、倍率和读写行为 |
| `APP/HeaderFiles/contest_modbus.h` | 寄存器索引和数量 |
| `APP/Function/contest_storage_final.c` | CSV 路径、表头、列和格式 |
| `APP/User/contest_main.c` | 初始化顺序、调度周期和任务接入 |
| `APP/ThirdParty/FreeModbus/port/contest_port_clocked.c` | 串口、方向和 RTU 定时 |
| `BootLoader/Function/bl_core.c` | 升级接收、擦写与跳转主流程 |

### 3.3 当前 RS485 引脚

```text
PD5 = USART1_TX
PD6 = USART1_RX
PE8 = RS485 DE/RE 方向控制
```

开发板已带 RS485 收发器时，USB-RS485 只连接板端 A、B 及必要的通信地，不直接接 PD5/PD6。

## 4. 建立不会丢失工作的工程习惯

比赛前和现场都保留三个目录：

```text
01_原始模板_只读
02_最近可编译版
03_当前工作版
```

1. 原始模板绝不修改。
2. 每完成一个可独立评分功能，就更新“最近可编译版”。
3. 现场修改只在“当前工作版”进行。
4. 编译失败超过 10 分钟且原因不明确，回退后用更小改动重做。
5. Keil Clean 不是备份，它不能恢复源码。

## 5. Keil 构建、地址和烧录

### 5.1 构建 APP

打开 `APP/MDK/CIMC_APP.uvprojx`，执行 Rebuild。通过标准：

```text
0 Error(s), 0 Warning(s)
```

当前基线约为：

```text
Code=39792  RO-data=5792  RW-data=440  ZI-data=11224
APP 链接起始地址=0x08011000
```

小改动导致资源突然大幅增长时，应检查大数组、重复库和重复源文件。

### 5.2 构建 Bootloader

打开 `BootLoader/MDK/CIMC_BL.uvprojx`，同样 Rebuild 并确认 0 错误、0 警告。

### 5.3 当前有效分区

| 区域 | 起始地址 | 大小 |
|---|---:|---:|
| Bootloader | `0x08000000` | 64KB |
| 参数区 | `0x08010000` | 4KB |
| APP | `0x08011000` | 128KB |
| APP 备份 | `0x08031000` | 128KB |
| 固件暂存 | `0x08051000` | 128KB |

Bootloader 目录还残留一套以 `0x0800D000` 为 APP 起点的旧定义。当前主路径不使用它，禁止混用两套分区。

### 5.4 正确烧录

1. Bootloader 烧到 `0x08000000`。
2. APP 烧到 `0x08011000`。
3. 烧 APP 时不能再次整片擦除，否则会擦掉 Bootloader。
4. 核对 HEX/BIN 时间戳是本次构建。
5. 烧录后断电重启，验证脱离调试器仍能运行。

最终通过标准：下载 Verify 成功、断电重启后 Modbus 可重新连接、采样计数持续增长。

## 6. Modbus 从零理解

### 6.1 默认参数

```text
Modbus RTU 从站，地址1，USART1/RS485，19200，8N1
```

### 6.2 人类编号与 PDU 地址

上位机填写的是 0 基 PDU 地址：

| 人类编号 | PDU 地址 | 内容 |
|---:|---:|---|
| 30001 | 0 | 电流 mA×1000 |
| 30002 | 1 | 电压1 V×1000 |
| 30003 | 2 | 电压2 V×1000 |
| 30004 | 3 | 状态位 |
| 30005 | 4 | 采样计数高16位 |
| 30006 | 5 | 采样计数低16位 |

读取 30001 时，报文起始地址写 `0000`，不是十进制 30001。

### 6.3 已成功报文解析

```text
请求：01 04 00 00 00 01 31 CA
响应：01 04 02 00 00 B9 30
```

请求依次是从站、功能码、起始地址、数量、CRC；响应依次是从站、功能码、字节数、数据、CRC。Modbus CRC 在总线上低字节先发送。

### 6.4 六寄存器测试

上位机设置：

```text
类型=输入寄存器，功能码=04，起始地址=0，数量=6
```

连续读取两次，采样计数应增长：

```text
sample_count = (30005 << 16) | 30006
```

例如高字为 1、低字为 10，计数为 `1×65536+10=65546`。

### 6.5 状态位

```text
30004 bit0：电流断线
30004 bit1：TF 卡初始化成功
30004 bit2：TF 卡运行错误
```

```c
wire_break = (status & 0x0001) != 0;
tf_ready   = (status & 0x0002) != 0;
tf_error   = (status & 0x0004) != 0;
```

### 6.6 异常响应

| 异常码 | 意义 | 优先检查 |
|---:|---|---|
| 01 | 非法功能 | 是否支持该功能码 |
| 02 | 非法地址 | 地址、数量、0/1 基差异 |
| 03 | 非法数值 | 写入范围和数量 |
| 04 | 设备故障 | 回调或硬件操作 |

收到异常响应说明物理链路和解析已经成功，不等于“通信不通”。

## 7. 比赛上位机操作

启动 `上位机/CIMC_DebugTool.exe`，选择正确 COM，设置 `19200、None、8、1、从站1`。

### 7.1 实时监控

1. 轮询周期先用 500ms。
2. 勾选“同时保存 CSV”。
3. 点击“开始轮询”。
4. 观察 TX/RX 同步增长、ERR 为 0、采样计数单调增长、三条曲线更新。

### 7.2 冻结与回放

1. 运行 30 秒后冻结曲线。
2. 等待 20 秒，确认采样计数和 CSV 仍增长。
3. 解除冻结，确认曲线恢复最新数据。
4. 停止轮询并导出 PNG。
5. 清空数据后导入刚生成的 CSV，确认曲线恢复。

“冻结”只停止重绘，不应停止通信或记录。

### 7.3 原始报文页

用于核对 CRC、新寄存器、非法地址和异常帧。实时轮询时不要再用其他串口软件占用同一 COM 口。

## 8. 三通道测量

### 8.1 信号链

4~20mA 和 0~10V 通常先经过采样电阻、分压、隔离、放大和保护，再成为 ADC 可接受的端电压。当前软件公式：

```text
工程量 = ADC端电压 × gain + offset
```

默认 gain `10、5、5` 只是占位值，实板标定前不能据此承诺精度。

### 8.2 当前通道映射

```text
逻辑通道0 → AD3344 Channel 4 → 电流
逻辑通道1 → AD3344 Channel 5 → 电压1
逻辑通道2 → AD3344 Channel 6 → 电压2
```

只改变一路输入时，如果另一路明显变化，应先检查端子、通道映射和串扰，不要先改增益。

### 8.3 安全原则

1. 先确认采样板端子定义和允许范围。
2. 不把 10V 直接接 MCU/ADC 引脚。
3. 隔离通道不要随意把所有地短接。
4. 改接线前停止信号源或断电。
5. 第一次上电使用限流并观察温升。

## 9. 标定方法

### 9.1 测试点

```text
电流：4、8、12、16、20mA
电压1：0、2、4、6、8、10V
电压2：0、2、4、6、8、10V
```

每点等待稳定，记录至少 20 个样本的平均值，并填写标准源值、万用表值、ADC 端电压、程序值和误差。

### 9.2 求增益和偏移

```text
gain   = (Y_high - Y_low) / (X_high - X_low)
offset = Y_low - gain × X_low
```

X 是 ADC 端电压，Y 是真实工程量。例如标准 0V/10V 对应 ADC 0.012V/2.006V：

```text
gain ≈ 5.015045
offset ≈ -0.060181V
```

写回 `contest_config.h`，重新构建、烧录，再用全部中间点回归验证。两点拟合不能证明全量程线性。

### 9.3 误差定义

```text
绝对误差 = 测量值 - 真值
相对读数误差 = |测量值-真值| / |真值| ×100%
满量程误差 = |测量值-真值| / 满量程 ×100%
```

0V 点不能算相对读数误差。正式题规定哪一种，就严格使用哪一种。

## 10. 电流断线测试

当前逻辑：电流低于 3.5mA 置位断线。

| 条件 | 预期 |
|---|---|
| 4mA | 不断线 |
| 开路 | 断线 |
| 3.4mA | 断线 |
| 3.6mA | 不断线 |
| 阈值附近反复变化 | 观察是否抖动 |

若抖动，可用迟滞和连续次数，例如连续 3 次低于 3.5mA 置位、连续 3 次高于 3.8mA 清除。仍必须先测开路时硬件前端的真实输出。

## 11. TF 卡测试

当前文件为 0:/CIMC_DATA.CSV，表头为 time_ms,current_mA,voltage1_V,voltage2_V,wire_break，默认每 1000ms 写一行。time_ms 是上电后的系统毫秒数，不是 RTC 日期。

基本步骤：

1. 使用已知正常的 FAT/FAT32 卡。
2. 断电插卡，再给开发板上电。
3. 读取 30004，bit1 应置位。
4. 运行至少 2 分钟。
5. 正常断电后取卡到电脑查看 CSV。
6. 检查只有一个表头、每行列数一致、时间基本递增 1000ms。
7. 比较 TF CSV 与同一时刻上位机数据。

还应测试不插卡启动、不可识别卡、写卡时持续 Modbus 轮询，以及在准备好恢复方法后测试运行中拔卡。

当前限制：TF 初始化失败不会自动重试，运行中拔卡后也不会自动重挂载。正式题若要求热插拔，需要实现关闭、卸载、延时和重挂载状态机。

## 12. Holding 寄存器为何能写但不生效

| 寄存器 | 当前预留含义 |
|---:|---|
| 40001 | 采样周期 |
| 40002 | 日志周期 |
| 40003 | 日志使能 |

FreeModbus 写回调会更新 RAM 数组，所以功能码 06/10 可以返回成功。但调度器周期仍来自编译常量，当前写入不会改变实际任务，也不会掉电保存。

正式题要求动态参数时，需要完整实现：

1. 校验地址和数值范围。
2. 合法值更新运行时配置。
3. 调度器使用变量，而不是固定常量。
4. 明确立即生效还是重启生效。
5. 掉电保存使用带魔术字、版本和 CRC 的结构。
6. 上电加载失败时恢复安全默认值。
7. 非法写入不改变旧值，并返回合适异常。

## 13. 收到正式题后的做法

第一遍只圈硬约束：必须、不得、仅允许、至少、不大于、不小于，以及地址、单位、倍率、字节序、周期、超时、精度、默认值、掉电保存、文件格式、PCB、匿名和提交要求。

第二遍填写 资料库/04_现场表单/现场改题记录表.md：

| 需求 | 模板值 | 正式题值 | 代码位置 | 验证方法 |
|---|---|---|---|---|
| 从站地址 | 1 | 待填写 | config | 上位机读取 |
| 采样周期 | 100ms | 待填写 | config/main | 计数/逻辑分析 |
| 文件名 | CIMC_DATA.CSV | 待填写 | config/storage | 读卡检查 |

不确定的条款写待确认，不要凭经验补答案。

第三遍执行最小修改：

1. 先改确定的常量。
2. 再改寄存器定义和回调。
3. 再改业务行为。
4. 再改文件格式。
5. 最后处理扩展功能和界面。

每完成一个功能组立即编译。不要一次修改十个文件后再第一次构建。

每条需求形成闭环：

    需求：读取两路0至10V，单位1mV
    代码：contest_app.c 和 contest_modbus.c
    验证：输入0、5、10V并读取寄存器
    证据：抓包、CSV、照片、标定记录

答辩时也按需求、代码、验证、证据讲。

| 阶段 | 时间比例 | 目标 |
|---|---:|---|
| 读题和差异表 | 10% | 不遗漏硬约束 |

## 15. 故障定位

完全无响应时按顺序检查：

    COM是否正确
    → 是否被其他软件占用
    → 19200、8N1、地址1
    → A/B是否接反
    → APP是否运行
    → MCU RX是否有波形
    → RX中断是否进入
    → RTU定时器是否判帧
    → eMBPoll是否执行
    → PE8是否切换方向
    → MCU TX和A/B是否回复

| 现象 | 优先检查 |
|---|---|
| TX 增长、RX=0 | 接线、地址、波特率、APP、DE/RE |
| 有 RX 但 CRC 错 | 参数、干扰、接地、回波、方向切换 |
| 只成功一次 | 回复后未切回接收、标志未清 |
| 数值为 0 但响应合法 | 信号源、端子、前端供电、通道、增益 |
| 数值跳动大 | 输入悬空、模拟地、参考、噪声、串扰 |
| 插 TF 后超时 | f_sync 耗时、卡质量、周期、主循环阻塞 |

合法的零值不是通信故障。应从信号源查到 ADC 原始电压，再检查换算公式。

## 16. 长时间稳定性

先做 10 分钟快速测试：上位机周期 500ms，同时写 PC CSV 和 TF，ERR 为 0，采样计数持续增长，曲线不停止。

再做 30 分钟常规测试：三路保持中间量程，每 5 分钟记录数值和错误计数，观察温漂、通信和存储并发。

边界测试包括最小和最大输入、电流开路恢复、非法寄存器、非法写值、不插卡启动、PC 重新连接和开发板复位。每项必须先写预期结果，否则只是尝试，不是可判定测试。

## 17. Bootloader 学习与风险边界

当前 Bootloader 能构建，但主功能未验证完之前不要测升级。

主流程：APP 请求升级，Bootloader 接收开始命令，按 256 字节分片接收，擦写 APP，校验后跳转 0x08011000。

已知限制：

- 当前 Modbus APP 没有处理初赛 0x0501 进入升级命令。
- Bootloader 接收 RAM 缓冲约 48KB。
- 固件要求魔术字 5A A5 C3 3C。
- 升级前必须准备调试器直烧恢复方法。
- 不能混用旧的 0x0800D000 分区定义。

正确顺序是先完成通信、采样、标定和存储，再备份板上 Flash，最后在可恢复条件下测试升级。

## 18. 提交和答辩

交付至少包括：

- APP、Bootloader 完整源码和 Keil 工程。
- 最终 HEX、BIN、AXF 和构建日志。
- 寄存器表、协议说明、标定记录和测试结果。
- TF 卡 CSV 示例。
- PCB、Gerber、BOM、端子和铜层编号检查。
- 方案、视频和现场要求的其他材料。

匿名检查应搜索学校、姓名、学号、教师、校徽、校园建筑、Windows 用户名和绝对路径，并检查图片 EXIF 和 Office 作者属性。

每项功能用五句话答辩：

1. 题目要求是什么。
2. 采用什么设计。
3. 代码在哪个模块。
4. 如何验证，结果是多少。
5. 当前限制与改进方向是什么。

## 19. 八节训练课程

### 第1课：通信基础

- [x] 读取 30001。
- [ ] 一次读取 30001至30006。
- [ ] 合并高低字并确认采样计数增长。
- [ ] 保存成功 TX/RX 日志。

通过标准：连续轮询 10 分钟，ERR=0，采样计数持续增长。

### 第2课：上位机数据工作流

完成实时曲线、冻结、PC CSV、PNG 导出和 CSV 回放。冻结期间 CSV 应继续增长，回放应恢复三条曲线。

### 第3课：通道识别

分别只改变一路输入。目标通道应明显变化，其他通道只有正常噪声。

### 第4课：完整标定

电流五点、两路电压各六点，求 gain 和 offset 并回归验证。误差计算严格按正式题定义。

### 第5课：断线和边界

完成 4mA、开路、阈值附近和恢复测试，状态应正确且可重复。

### 第6课：TF 卡

完成正常卡、不插卡、连续写入、通信并发和断电读卡。

### 第7课：模拟改题

人为改变从站地址、日志周期、文件名和一个寄存器倍率。先填差异表，再修改、构建、烧录、验证和回退。

### 第8课：整套限时演练

从备份工程开始，限时完成读需求、修改、构建、烧录、标定、异常测试和材料整理。最终工程必须脱离调试器，断电重启后独立运行。

## 20. 你现在立刻应该做什么
