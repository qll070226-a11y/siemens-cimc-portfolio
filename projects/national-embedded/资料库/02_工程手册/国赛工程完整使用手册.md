# 国赛工程完整使用手册

## 1. 文档目的

本手册用于在断网环境下快速理解、构建、修改和验证国赛模板。它不是正式赛题的替代品。收到现场题后，以现场题为最高优先级，并用“需求-代码-验证”方式逐项闭环。

## 2. 当前工程能做什么

APP 当前已经接入以下主链路：

1. 通过 GD30AD3344 SPI 驱动顺序读取三个物理通道。
2. 将一个通道换算为 mA、两个通道换算为 V。
3. 对电流通道做低阈值断线判断。
4. 用 FreeModbus 运行 RTU 从站，默认地址 1、19200、8N1。
5. 将测量值发布到输入寄存器，将三项配置放入保持寄存器。
6. 将测量值按 CSV 追加到 TF 卡 `0:/CIMC_DATA.CSV`。
7. 用无操作系统轮询调度器周期运行通信、采样、存储、告警和 UI。
8. APP 和 Bootloader 均已在本机 Keil ARMCLANG 6.24 下构建通过。

“构建通过”只证明语法、链接和工程依赖成立，不证明 ADC 比例、隔离性能、TF 卡兼容性、RS485 电气方向或 Bootloader 实机擦写正确。

## 4. 软件环境

当前已验证环境：

- Keil 可执行文件：`%LOCALAPPDATA%\Keil_v5\UV4\UV4.exe`
- 编译器：ARMCLANG 6.24
- GD32 Pack：`%LOCALAPPDATA%\Arm\Packs\GigaDevice\GD32F4xx_DFP\3.0.3`
- 目标器件/工程配置以 `.uvprojx` 为准。

比赛前不要升级 Keil、编译器或 Pack。离线环境中，工具链变化造成的问题通常比代码问题更难恢复。

## 5. 第一次构建

### 5.1 图形界面

1. 打开 `APP\MDK\CIMC_APP.uvprojx`。
2. 确认目标为工程内已有 Target。
3. 执行 Rebuild。
4. 构建日志应为 `0 Error(s), 0 Warning(s)`。
5. 输出位于 `APP\MDK\output`，重点保留 `.axf`、`.hex`、`.bin`。
6. 再打开 `BootLoader\MDK\CIMC_BL.uvprojx` 重复操作。

### 5.2 命令行

在工程根目录运行：

```bat
tools\rebuild_keil.bat
```

然后运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools\verify_build_outputs.ps1
```

如构建脚本无法找到 Keil，先打开脚本检查其中路径，不要移动整套 Keil 目录。

## 6. 上电启动顺序

`contest_main.c` 的关键顺序如下：

1. `SCB->VTOR = FLASH_APP_ADDR`：将中断向量指向 APP 起始地址。
2. 初始化 SysTick 和周期计数器。
3. 延时 200ms，给电源和外设稳定时间。
4. 初始化 LED、按键、OLED、外部 Flash。
5. 初始化串口、GD30AD3344、片内 ADC、DAC、RTC、SD/FatFs。
6. 加载原工程参数，初始化告警、UI 和比赛应用。
7. `contest_app_init()` 挂载 TF 卡并启动 FreeModbus。
8. 主循环不停运行轻量调度器。

如果程序在初始化阶段卡死，按这个顺序逐个屏蔽外设定位。不要同时注释多项，否则无法确定根因。

## 7. 任务调度模型

默认任务：

| 任务 | 周期 | 作用 |
|---|---:|---|
| `contest_modbus_task` | 1ms | 调用 `eMBPoll()` 处理 FreeModbus 事件 |
| `contest_sample_task` | 100ms | 三通道采样、换算、状态和寄存器更新 |
| `contest_storage_task` | 1000ms | 追加一行 CSV 并 `f_sync` |
| `alarm_check` | 100ms | 原工程告警 |
| `ui_task` | 50ms | 原工程 UI |

调度器是合作式轮询：任何任务阻塞，后续任务都会延迟。TF 卡写入、串口打印和外设等待均应有上限。现场若将日志周期改得很短，必须重新测试 Modbus 连续轮询是否超时。

## 8. 三通道采样链路

`contest_adc_read_voltage()` 将逻辑通道 0/1/2 映射到 GD30AD3344 Channel 4/5/6，并使用 `GD30AD3344_PGA_4V096` 量程读取 ADC 端电压。

工程量公式：

```text
电流(mA) = ADC端电压(V) × CURRENT_GAIN + CURRENT_OFFSET
电压1(V) = ADC端电压(V) × VOLTAGE1_GAIN + VOLTAGE1_OFFSET
电压2(V) = ADC端电压(V) × VOLTAGE2_GAIN + VOLTAGE2_OFFSET
```

模板默认 `10、5、5` 只是占位比例。实际比例由采样电阻、分压、隔离放大器增益、参考电压和器件误差共同决定。未标定不得宣称达到 ±1%。

当前三个通道在同一个 100ms 任务内依次读取，满足持续多通道采集的软件框架，但不是严格同时采样。若现场题要求相位同步或同一触发沿，需要改成 ADC 芯片支持的同步/扫描机制并核对硬件。

## 9. 标定最短方法

每个通道至少取低点和高点求一次线性系数，再用中间点验证。设信号源真实值为 `Y`，程序可观测的 ADC 端电压为 `X`：

```text
gain   = (Y_high - Y_low) / (X_high - X_low)
offset = Y_low - gain × X_low
```

推荐电流测 4、8、12、16、20mA；电压测 0、2、4、6、8、10V。每点等待稳定并取多次平均。完整流程见 `03_专题速查/4-20mA与0-10V标定.md`。

## 10. 断线检测

当前逻辑为：

```text
current_mA < 3.5mA => wire_break = 1
```

该值低于正常 4mA 下限，留有 0.5mA 裕量。现场应检查开路时前端实际输出；有些隔离前端开路不会变成 0。若边界抖动，应增加迟滞，例如低于 3.5mA 置位、高于 3.8mA 清除，并连续 N 次确认。

## 11. Modbus RTU

默认参数：从站 1，19200bps，8 数据位，无校验，1 停止位。FreeModbus 的串口和定时器端口使用 `contest_port_clocked.c`，中断入口通过比赛版 IRQ 文件转发。

输入寄存器从协议地址 1 开始：

| 人类编号 | 值 | 单位/倍率 |
|---:|---|---|
| 30001 | 电流 | mA ×1000 |
| 30002 | 电压 1 | mV |
| 30003 | 电压 2 | mV |
| 30004 | 状态位 | bit0 断线，bit1 TF ready，bit2 TF error |
| 30005 | 采样计数高 16 位 | 无 |
| 30006 | 采样计数低 16 位 | 无 |

保持寄存器 40001~40003 当前可读写，但写入只改变 RAM 数组，不会改变调度器和存储逻辑。这是最容易误判的“预留功能”。正式题若要求参数生效，需在写回调中校验范围、更新运行配置，并按要求做掉电保存。

注意上位机常把 30001 显示为偏移地址 0。以报文 PDU 地址为准，避免差 1。

## 12. TF 卡日志

启动时执行：磁盘初始化 → FatFs 挂载 → 打开/创建 CSV → 空文件写表头。每个日志周期重新打开文件，移动到末尾，写一行，`f_sync`，关闭。

CSV 列：

```text
time_ms,current_mA,voltage1_V,voltage2_V,wire_break
```

时间是上电后的系统毫秒，不是 RTC 日期。采用整数拆分输出三位小数，避免嵌入式 `printf` 浮点配置问题。

当前限制：启动未挂载成功时不自动重试；运行中拔卡后 `tf_error` 置位，不自动重新初始化。若正式题要求热插拔，应加卡检测、关闭文件、卸载、延时和重挂载状态机。

## 13. Bootloader 与 APP

初赛权威分区及当前主升级路径：

| 区域 | 起始 | 结束 | 大小 |
|---|---|---|---:|
| Bootloader | `0x08000000` | `0x0800FFFF` | 64KB |
| 参数 | `0x08010000` | `0x08010FFF` | 4KB |
| APP | `0x08011000` | `0x08030FFF` | 128KB |
| APP 备份 | `0x08031000` | `0x08050FFF` | 128KB |
| 固件暂存 | `0x08051000` | `0x08070FFF` | 128KB |

APP 实际链接和向量表均从 `0x08011000` 开始；`bl_core.c` 也通过 `ota_def.h` 擦写和跳转到该地址。

但 Bootloader 目录中另有 `bl_partition.h`/`bl_param.h`，定义 48KB Bootloader、`0x0800C000` 参数和 `0x0800D000` APP1。这套定义被 `bl_flash_if.c` 等遗留底层引用，但当前 Keil 工程的主升级文件 `bl_core.c` 没有使用它。现场不要把遗留的参数管理模块随意接入主流程，否则会擦写错误区域。详细审计见 `Flash分区与Bootloader.md`。

## 14. 现场改题策略

推荐按以下顺序：

1. 通读正式题，做需求差异表。
2. 先只改 `contest_config.h` 中确定的常量。
3. 修改寄存器表时同时改头文件、回调和文档。
4. 修改周期为运行时参数时，将任务周期从常量改为可校验变量。
5. 修改 TF 格式时先写出一行示例，和题目逐字符核对。
6. 每次改动后构建，再上板验证。
7. 依次闭环：串口连通 → 三通道原始量 → 标定 → 文件 → 异常 → 长稳。

## 15. 推荐测试顺序

### 15.1 上电冒烟

- 电源电流无异常，芯片不过热。
- 调试串口出现 ready 信息。
- OLED/LED 不影响主循环。
- TF 插入和不插入均不应死机。

### 15.2 通信

- 地址 1，19200 8N1 能读 30001~30006。
- 无效地址返回异常或无响应符合协议。
- CRC 错误不应修改寄存器。
- 连续轮询至少 10 分钟无卡死。

### 15.3 测量

- 分别施加电流和两路电压。
- 检查通道映射没有串线。
- 完成多点标定并算最大误差。
- 一个通道变化时，另外两路检查串扰。
- 电流开路后状态 bit0 置位，恢复后清除。

### 15.4 存储

- 空卡首次生成表头。
- 运行后记录条数与时间基本一致。
- 正常断电后文件可读。
- 写入时持续轮询 Modbus，检查超时。

### 15.5 升级

- 只在保存了可恢复烧录方式后测试。
- 核对固件前四字节魔术字 `5A A5 C3 3C`。
- 上位机按 256 字节切片发送，切片约 5ms。
- 擦写后复位，Bootloader 从 `0x08011000` 校验向量并跳转。

提交前保留：源工程、构建日志、hex/bin、寄存器表、标定记录、测试结果、PCB/Gerber/BOM、方案电子版。匿名材料不得出现学校、姓名、校徽、建筑图、用户名路径或图片元数据等身份信息。

答辩时按“需求 → 设计 → 实现 → 证据 → 限制”叙述。不要只说“实现了”，应给误差表、通信抓包、CSV 样例和异常测试结果。

## 17. 当前禁止直接承诺的内容

- 未经标定就承诺 ±1%。
- 将三次顺序采样称为严格同步采样。
- 称保持寄存器写入会动态生效或掉电保存。
- 称 TF 卡支持热插拔自动恢复。
- 称 Bootloader 已在真实硬件完成升级验证。
- 称电气隔离可由软件证明。

这些能力可以在现场补全，但在补全并验证前必须如实标记。
