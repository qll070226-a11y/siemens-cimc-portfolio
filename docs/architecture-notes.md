# 面向科研导师的架构摘要

## 研究/工程问题

项目把工业现场的“模拟量采集、协议通信、边缘存储和远程升级”串成一条可验证链路。难点不只是驱动外设，而是让采样结果在异常、断网、TF 卡失败、协议非法请求和升级中断时仍能保持可解释、可恢复的状态。

## 关键设计决策

| 问题 | 设计决策 | 可验证证据 |
|---|---|---|
| 多通道采样如何复用业务数据 | 采样任务生成业务数据快照，Modbus 和 CSV 只消费快照 | 需求-代码-验证矩阵、CSV 样例 |
| 如何控制实时性 | 裸机合作式调度，通信高频、采样中频、存储低频 | 任务周期表、长时间轮询测试 |
| 如何避免模拟量直接暴露给协议层 | ADC、换算、状态判断、寄存器发布分层 | `contest_adc.c` / `contest_app.c` / `contest_modbus.c` |
| 如何处理升级风险 | Bootloader 独立构建，包头/CRC/备份/回滚分阶段处理 | 分区说明、OTA 文档、恢复流程 |
| 如何让结果可复核 | 统一配置入口、构建基线、SHA256、验收表单 | `资料库/05_构建基线` 与 `04_现场表单` |

## 面试时可展开的方向

- 将合作式调度迁移为事件驱动或 RTOS 任务时，如何保持 Modbus 时序和 TF 写入的实时性。
- 三通道顺序采样与严格同步采样的差异，以及 ADC MUX 残留、采样保持和串扰的实验设计。
- 将保持寄存器从“RAM 预留”扩展为带范围校验、版本号、魔术字和 CRC 的掉电参数存储。
- 为 TF 卡热插拔增加状态机、重挂载和写入幂等性。
- 用自动化测试生成 Modbus 帧、校验异常响应并回放 CSV，构建硬件在环测试闭环。
